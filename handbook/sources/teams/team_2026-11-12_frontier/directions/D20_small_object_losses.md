# D20 Small-structure and instance-wise losses

Scout: literature only (no runs, no test data read). Written 13 Nov 2026, resumed after a dropped session.
R = what the paper measured. S = my judgement. E = numbers from BRIEF.md.

## Why this direction fits our data (S)
- E: 76 to 88% of crack components are under 20 px; on E1, 70% of crack pixels get p(crack) < 0.001; components >= 20 px found 0.798 (single) / 0.834 (ensemble).
- Pixel losses (CE, soft Dice) give a component weight proportional to its pixel count, so short or faint cracks and small inactive patches carry almost no gradient. Instance-wise losses give every connected component its own term.
- Main risk specific to us: label fragmentation. A 1 to 2 px traced line breaks into many tiny components (jitter, gaps, speck labels as in H36). An instance loss would then upweight annotation fragments. Every arm below must first merge fragments into crack instances (8-connectivity after a radius 2 to 3 px closing, or grouping components within 3 px) and drop specks under 3 px. Cheap CPU check first: the component size histogram on train labels after closing at r = 1, 2, 3.
- Second adaptation: define the bag or cell of each crack instance on the GT dilated by 2 px, so the instance term tolerates the 1 to 2 px jitter (a perfect mask shifted 1 px scores IoU 0.56).

## Minimum experiments (house = U-Net++ R34, 5 seeds, 20k steps; same seed rule as before)
1. CATMIL-MIL: house + MIL (lambda 0.2) on merged, 2 px dilated crack and inactive instances; house and PF variants. Metrics: E1 crack relF1@2 and relR@2; test clean-49 component recall < 20 px and >= 20 px at relP@2 >= 0.90; crack IoU. Kill: E1 relF1@2 gain < +0.02, or test crack IoU drop > 0.012 with no relF1@2 gain. About 12 GPU-h.
2. BiCC alpha in {0, 0.5}: replace soft Dice on crack and inactive with the BiCC term. Metrics: component F1 on merged instances (test, E1), relF1@2, crack and inactive IoU. Kill: component F1 not above house by 0.02 on both sets. About 14 GPU-h.
3. Inverse-size CE weights (gamma 0.5): cheapest training arm. Same metrics and kill as 2. About 6 GPU-h.
4. VCAP / SADL decision layer on existing 5-seed ensemble probability maps: fit on val + F51 or CV out-of-fold maps, evaluate once on test and E1. Kill: relF1@2 gain < 0.005 and component F1 gain < 0.01. Under 1 GPU-h if maps are saved.
5. Recall loss and multi-class component loss for other classes: metric mIoU_rob and per-class gridline / splice IoU. Kill: mIoU_rob < house + 0.005.

## Overlap with BRIEF section 5 (honest)
- Skeleton Recall (w 1.0, 0.1): different mechanism, same aim (recall on thin structures). It widened predictions. MIL acts on one pixel per instance and should widen less; still watch predicted crack width.
- Offset-tolerant CE (n.d.): related to the 2 px dilated bags and DBCE, but those change instance or class weighting, not target placement.
- Logit bias and per-module thresholds: global or per-module. VCAP / SADL act per component (peak prob, size bucket). BiCC shows a global threshold cannot reproduce a loss-level precision-recall shift.
- Dice on 12 classes (worse): partial overlap with the multi-class one-vs-rest averaging (row 7), not with its per-component part.
- No component-wise, instance-wise, MIL or long-tail loss has been run (BRIEF 5 lists them as open).

## Rejected (one line each)
- ICI loss (arxiv:2304.06229): superseded by the 2024 instance loss family from the same group and by CATMIL / BiCC.
- All Sizes Matter (doi:10.1007/978-3-031-76163-8_16): blob loss in a BraTS-METS ensemble; useful only as evidence that small-lesion-only models hurt the ensemble while post-processing helped a lot.
- SD loss + pinwheel conv (doi:10.1609/aaai.v39i9.32996): IR blob targets; the location term assumes compact Gaussian targets, not lines.
- S3-Mamba (doi:10.1609/aaai.v39i7.32824): an architecture, belongs to D22 / D09; its size-based curriculum is the only loss-side idea.
- Region-wise loss / RRW maps (doi:10.1016/j.patcog.2022.109208): a distance-map boundary loss; belongs to D18.
- Adaptive focal loss with size + smoothness (arxiv:2407.09828): single-object tumour Dice; smoothness term meaningless for 1 to 2 px lines.
- Complex wavelet MI loss (arxiv:2502.00563): multi-scale MI loss, belongs to D28 frequency priors.
- Loss function inversion for steel bridge cracks (doi:10.1016/j.autcon.2024.105896): close domain (thin cracks, many decoys) but I could not read how the loss works; worth a D09 / D13 look.
- Pixel-wise modulated Dice (doi:10.1109/access.2026.3683817), Balance loss (doi:10.1609/aaai.v39i8.32956): difficulty / class reweighting, no instance mechanism.
- Normalized Wasserstein distance (arxiv:2110.13389): box detection metric, not segmentation.
- Count-aware losses: search found only crowd counting and referring segmentation; nothing usable.

## Gaps
- No paper tested instance-wise losses on 1 to 2 px curvilinear labels with jitter. Every result above is on blob-like lesions. The fragment-merging step is our own design and must be checked first.
- search_snippets was rate-limited; I could not pull evidence on how blob / CC losses behave with fragmented or noisy instance labels.
- CC-DiceCE code found only through a web search summary; repository contents not checked. panoptica repo unverified. Shirokikh 2020 abstract missing from the index.
- Component-level hysteresis (keep weak pixels connected to a strong seed) is a classic trick with no recent paper found here; worth one cheap post-processing arm alongside SADL.
- Tiny-object tricks outside losses (crop oversampling of crack regions, nnU-Net foreground oversampling, higher-resolution decoder heads) belong to D22 / D25 / D37.

## Context (from verified results)
- PF (freeze encoder 1,000 steps, then 0.1x LR) is replicated: PF2 E1 inactive IoU 0.048 -> 0.237 BETTER; PF2E ensemble E1 inactive +0.21 PASS. Test flat.
- Open problem: E1 crack recall ~0.2, failure concentrated in half-cut + scuff cells. Test crack IoU ~0.49 is near the labelling ceiling.
- Dropped: pool routes (MIM, CP, SSL), per-panel thresholds, intensity normalisation, neighbour reference, TTA, RN50-PF.
- Lesson: preserved general features help unseen panels; cracks are 2-3 px.
- Baseline for every arm: SUP100-PF (R34 U-Net++), seeds 5-9.

## A1. Two-branch encoder: frozen/PF foundation + high-resolution CNN branch (top pick)
- Branch 1: DINOv3 ConvNeXt-T (weights already on gaint, checked), PF-style or mostly frozen.
- Branch 2: light high-res CNN (stride <= 2), fine detail only.
- Fuse in the decoder (concat or gated fusion at each scale).
- Check: reuse el_f8 hrstem wrapper; relation to the A8 screen (DINOv3 probe) so this is not a repeat. Memory beside finllm.
- Expected (S): E1 crack recall up if general features carry over; test flat to small gain.
- Kill: no E1 crack relF1@2 or recall gain vs SUP100-PF and/or test WORSE.

## A2. Style-invariant early layers (IBN-Net style)
- Instance norm in the first encoder stages (part of the channels), batch norm kept deeper.
- Rationale: new panels differ mainly in brightness/contrast/texture (style); IN removes per-image style.
- Check: interaction with PF (changes pretrained layers: decide IN init / where to insert so PF still preserves features). Literature: IBN-Net, domain generalisation in segmentation.
- Cost: ~1 h code, one 5-seed arm.
- Kill: E1 crack and inactive not better and/or test WORSE.

## A3. Geometry-aware input / conditioning
- Give the model cell structure: busbar positions, cut-line mask, cell type (half/full).
- As extra input channels or FiLM conditioning.
- Rationale: model confuses the half-cut cut line and spacing with defects.
- Check: can busbar/cut-line maps be derived automatically (projection profiles) for train, test, E1 and HC synthetic cells? Pair with idea 5 (HC) so the model sees half-cuts with geometry.
- Kill: no gain on E1 half-cut stratum and Hanifi half-cells (non-E1 check first).

## A4. Structured crack head (second round)
- Separate crack head predicting centreline map + local direction field + width.
- Rationale: cracks are continuous lines; direction helps connect fragments across busbars; fits component recall / relR@2.
- Check: relation to THIN-B3 results (Skeleton Recall, clDice). Run only if those leave crack recall weak.
- Kill: component recall at fixed precision not better.

## A5. Long-range context along the cell (second round)
- Axial (row/column) attention or line-scan block in the bottleneck/decoder.
- Rationale: cracks span whole cells and cross busbars; local receptive field breaks them.
- Check: cost on 2 lanes; prior long-range attempts in repo.
- Kill: no component recall / E1 crack gain.

## A6. Two-stage: cell-level gate + pixel head
- Cell classifier (cracked or not) gates the crack pixel head.
- Rationale: cuts false crack px on clean cells (rose with PF and CP); matches industry cell grading.
- Check: cell-level AUROC of current models from idea 7 metrics first; if already high, the gate is cheap.
- Kill: precision gain without recall loss not shown.

## Suggested order (S)
1. A2 (cheap).
2. A3 together with HC (idea 5).
3. A1 (biggest bet, best paper story), after the A8 screen result.
4. A4 / A5 / A6 only if crack recall is still weak after THIN-B3 and HC.
One change per arm, same commit and machine, E1 co-primaries pre-registered.

BenchmarkEL version: **`dataset_20211104`** (`class_info.py` header and README). Its folders give exactly
**478 train_original / 54 val / 50 test** and **24 classes** (`ListOfClassesAndColorCodes_20211104.csv`). The
names and RGB values in `class_info.py` match that CSV. `images_train_augmented` (1434 = 3 × 478, the
flip_180/mirror_180/rotate_180 copies) is **not** used by the code.

**Note A: masks.** The shipped masks are 8-bit indexed (mode `L`, values 0–23). The loader calls
`.convert("RGB")` and looks colours up in the palette. With the indexed masks symlinked directly, every non-background
class turns into `(v,v,v)`. That colour is not in the palette, so it becomes ignore=255. Over 25 train masks, **24.6 % of pixels became
ignore** and only background survived. The README and `class_info.py` say a prep step converts indexed → RGB, but
`download_data.sh` does not do this. I generated the RGB masks with `CLASS_COLORS[coded]` and checked that every
mask round-trips through the repo loader to the identical class map (582/582). No code was changed.

**Note B: splits.** `data/splits/` is in `.gitignore`. No split file exists in git history, the notebook, or
anywhere on disk. The README calls the splits "committed", but they are not. `prepare_splits.py` would *reshuffle* the 582
images into 466/58/58, so it cannot reproduce 478/54/50. The 478/54/50 numbers match the official folders, so
train/val/test come from those. The 50/20/10 % subsets (239/95/47) cannot be recovered.
**Hazard:** if a split file is missing, `train.py` falls back to `stem_list=None`, which means *every PNG in
`data/labeled/images`*, including val and test. Running `ssl_{50,20,10}pct.yaml` right now would therefore silently train on all 582
labelled images, test set included.

## 3. albumentations / GaussNoise

`grep var_limit|GaussNoise|std_range` found 2 hits, both in `src/data/augmentations.py`:

| line | code | effect under 2.0.8 |
|---|---|---|
| 94 (`get_strong_augmentation`, used by the supervised baseline) | `A.GaussNoise(var_limit=(10.0, 50.0), p=p_noise)` | `var_limit` **is silently dropped** (UserWarning only). The transform falls back to the default `std_range=(0.2, 0.44)` |
| 183 (`get_strong_photometric`, SSL student) | `A.GaussNoise(p=p_noise)` | default `std_range=(0.2, 0.44)` |

**Neither call uses the 2.x `std_range` argument.** Measured on a flat 128-gray image: the as-is code gives a noise
std of **51–86 / 255**. The intended `var_limit=(10,50)` (σ = 3.2–7.1) corresponds to
`std_range=(0.0124, 0.0277)`, which measured 2.9–6.7. **So the noise is about 10–15× stronger than intended, on 30 % of samples.** You can see it
in `aug_check.png`. Not fixed.

# x4_pixcon: cross-image pixel contrast with hard anchors (builder loss; ledger P275)

## What it changes
Wang et al., Exploring cross-image pixel contrast for semantic segmentation (ICCV 2021) / Cross-image pixel contrasting for semantic image segmentation (IEEE TPAMI 2024, doi:10.1109/tpami.2024.3367952), Sec. 3.2 and 3.3, after the official code (github.com/tfzhou/ContrastiveSeg: projection.py, loss_contrast_mem.py, trainer_contrastive.py):
- Projection head ('convmlp': 1x1 conv, BN, ReLU, 1x1 conv to 256, L2 norm) on the U-Net++ decoder output (16 channels, full resolution, the input of the segmentation head). The head is pointwise, so it runs on the sampled pixels only (an MLP; BN statistics over the sampled pixels). Train-only: own Adam (base lr, same schedule), grad clip 1.0, checkpointed (latest.pth models/optimizers/schedulers 'pixcon'); not part of the model, so inference, SWAD, BN re-estimate and dumps are unchanged.
- Segmentation-aware hard anchors: per image every labelled class with >= 10 px; n_view = min(1024 // classes in the batch, 100) anchors per class and image, half hard (labelled c, predicted != c: for crack, the missed crack px) and half easy; a short pool is refilled from the other and never indexed past (the official code can).
- Memory: per class a pixel queue (10 random px per class and image per step) and a segment queue (normalised mean embedding of up to 256 px per class and image), 1,000 each, detached embeddings of the same head pass (their keys); only filled slots are used (their code starts from random vectors).
- Loss (their _contrastive, Eq. 3): anchors vs memory + the batch's other anchors (self excluded), per-positive InfoNCE against the negatives, mean over positives, times -(0.1 / 0.07), mean over anchors; added as L_house + 0.1 L_NCE (their non-memory H48 config: tau 0.1, base 0.07, weight 0.1, max_views 100, max_samples 1024). Logged on the step line: loss_con, lambda, pc_anchors, pc_hard, pc_memory.
- Deviations (S): decoder output instead of the HRNet concat at 1/4 (keeps 1 to 2 px cracks), memory 1,000 not 5,000 per class (contrast matrix size; 425 train cells), semi-hard positive / negative sampling of the TPAMI text not implemented (their code uses the whole memory as well), no warm-up (their single-GPU trainer path does not apply it either).
- Keys: training.pixcon.{enabled=true, weight=0.1, proj_dim=256, memory_size=1000, temperature=0.1, base_temperature=0.07, max_samples=1024, max_views=100, min_px=10, pixel_per_image=10, seg_px=256}.
- Code: src/trainers/pixcon.py; src/trainers/trainer.py.
- Precomputed inputs: none. Run time (S): COMBO plus a few percent.

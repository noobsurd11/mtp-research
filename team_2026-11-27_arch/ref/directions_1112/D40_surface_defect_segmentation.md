# D40: Industrial surface defect segmentation, state of the art

Scout: D40. Date: 13 Nov 2026. Scope: steel, KolektorSDD2 (KSDD2), magnetic tile, wafers, PCB, fabric, rail. Supervised and mixed-supervision recipes, losses, few-shot, tiny-defect tricks that could move our five problems (BRIEF section 4).
Labels used below: R = what the paper measured, E = what our files measured (from BRIEF), S = my judgement.

## Summary (S)
- The industrial field is dominated by architecture tweaks (YOLO variants, attention U-Nets) evaluated on NEU-Seg, Magnetic Tile, KSDD2 with single runs. Little of it transfers. What does transfer is a small set of training-signal ideas that the KSDD2 / Severstal line (Skocaj group, Ljubljana) and a few loss papers developed for exactly our situation: few positive images, fuzzy annotation borders, extreme pixel imbalance, image-level labels available.
- Strongest transferable mechanisms for us: (1) loss shaping at uncertain label borders (Bozic distance-transform weighting, Xie label-confusion suppression, truncated losses in SuperSimpleNet); (2) an image-level presence head whose gradient pushes the encoder toward small, faint defects (Bozic, Sample-centric CaP); (3) per-batch class balancing by blending real rare-class regions into clean images (Dynamic Label Injection), which targets inactive / splice rather than crack; (4) one-sided relaxation of background loss for confident unlabelled defects (Boxes2Pixels), which targets the 24 of 239 train cells with crack label issues.
- One close-domain paper (Yi et al., mono PV cells with tiny hidden cracks at 1:2000 imbalance) gives FP/FN-regulated focal loss; small single-run gain.
- For the benchmark: SuperSimpleNet and SegDecNet (Bozic) are the standard KSDD2 baselines that run under unsupervised, weak, mixed and full supervision; a credible EL benchmark should include one of them. Sample-centric Seg_Recall and conformal risk control give cell-level and guarantee-style operating points that fit "captures almost all cracks".
- Many items found here are already held by other scouts (SuperSimpleNet D07/D21/D36, Bozic mixed supervision D27/D36, Boxes2Pixels D15/D36, GFDS/SOFS D38, PRN/SegAD D39, IDA 2026 cross-scenario D30, MVTec AD 2 D07). Rows below are kept only where D40 adds a different mechanism or adaptation; the overlap is stated in each row.

### Minimum experiments (one line each; house = U-Net++ / ResNet-34 recipe, PF = encoder-preserving variant; all use the existing module-grouped 5-fold CV on 532 cells plus clean-49 test and E1, 5 seeds or 5 folds; about 1.1 GPU-h per run)
1. Bozic DT weighting: arm = house + crack label dilated to 5 px with distance-transform weights (p = 1, then p = 2); baseline = house; metric = CV crack relF1@2 and strict IoU; kill if relF1@2 < +0.01 or IoU drops > 0.01. Add cls head as arm 1b (stop-grad), kill if cell-level crack recall < +0.02. About 12 GPU-h.
2. Balanced loss: arm = house with label-confusion suppression in a 1 px band + truncated CE (0.9) + dynamic class weights; baseline = house; metric = CV crack IoU, mIoU_rob; kill if both < +0.01. About 6 GPU-h.
3. CaP head: arm = PF + crack / inactive presence heads (cell and 128 px tile), weight 1; baseline = PF; metric = CV crack relR@2 at relP@2 >= 0.90 and cell-level Seg_Recall; kill if relR@2 < +0.02. About 6 GPU-h.
4. One-sided self-correction: arm = PF + background-loss drop for confident thin components > 2 px from labels after 5k steps; baseline = PF; metric = E1 crack relF1@2 and CV relR@2; kill if E1 relF1@2 < +0.02 and CV relP@2 falls > 0.02. About 6 GPU-h.
5. DLI: arm = house + Poisson-cloned inactive (+ attached crack), splice, edge_dark, per-batch balanced; baseline = house; metric = CV inactive IoU (not test, decided by 3 cells), splice IoU; kill if CV inactive IoU < +0.02 and splice stays 0. About 8 GPU-h.
6. SuperSimpleNet: arm = official code, binary crack / inactive, 512 px, full and weak (ELPV) regimes; baseline = house; metric = crack AP, relF1@2, E1 relF1@2; benchmark row regardless. Score kill: no gain as 6th ensemble member (< +0.01 relF1@2). About 6 GPU-h.
7. DIBE: arm = house with soft Dice replaced by DIBE_Reg (alpha 0.3, beta 0.7) on crack; baseline = house with logit bias chosen on val; metric = relR@2 at relP@2 >= 0.90; kill if < +0.02. About 6 GPU-h.
8. SPDCN: arm = house with ADADC in the last two decoder stages; baseline = house; metric = CV gridline IoU and crack relF1@2; kill if gridline IoU < +0.03 and crack n.d. About 8 GPU-h.
9. CADNet-style reference: arm = PF + distance map to a retrieved defect-free pool cell; baseline = PF; metric = E1 crack relF1@2, E1 half-cut false alarms; kill if E1 relF1@2 < +0.03. About 15 GPU-h (retrieval index + runs).
10. Conformal: no training. Calibrate on val + F51, report realised relR@2 and precision on test and E1; kill if realised recall on E1 falls below target by > 0.1 (shows the guarantee breaks under shift, itself a benchmark finding).
11. Rough-set boundary loss: arm = house with boundary-region loss on the 1 to 2 px ring + faint segments; baseline = house; metric = CV crack IoU; kill if < +0.01. About 6 GPU-h. Read full text first.
12. Texture debiasing: arm = house + background-prototype subtraction; baseline = house; metric = crack precision on multi cells (CV), material IoU; kill if multi-cell crack relP@2 < +0.02. About 8 GPU-h.

### Overlap with BRIEF section 5 (honest)
- Offset-tolerant CE was n.d.: rows 1, 2 and 11 are in the same family (tolerate border error). They differ: row 1 reweights inside a dilated label, row 2 truncates easy pixels and adds class weights, row 11 adds a confidence module. Treat row 2 as first, and drop 1 and 11 if 2 is n.d. and the tolerance band is the same.
- Crack copy-paste was n.d. (more decoys): row 5 is aimed at inactive and rare classes, not crack, so it is open.
- Dice on 3 classes n.d.; focal / Tversky never tried: row 7 is open.
- Classification heads, noisy-label methods, deformable / snake convs, reference-based inputs, conformal thresholds: never tried (BRIEF "never tried" list).
- Logit bias and per-module thresholds were tried: row 10 is a threshold method, but with a stated guarantee; its value is for the benchmark, not for score.

- Reference-based / change-detection segmentation for EL (row 9) deserves its own scout with module-level EL data (neighbour cells as references).

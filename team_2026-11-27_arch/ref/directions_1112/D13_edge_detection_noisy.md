# D13: Learned edge detection with crisp outputs and inconsistent annotations

Scout: D13 literature agent. First pass 12 Nov 2026, second pass 13 Nov 2026 (this version merges both). Literature only, no servers, no test data.
Tags: R = what a paper measured, E = what our files measured (from BRIEF), S = my judgement.

## Why this direction fits (S)
Our crack class is an edge-detection problem in disguise: 1 to 2 px targets, about 1 px annotator jitter, two annotations of the same cell agree at IoU 0.21 to 0.26 but 0.82 to 0.99 within 2 px (E). Edge detection has worked on exactly this for ten years. Three findings matter here:
1. Label misalignment, not the loss, is the main cause of thick, unsure predictions. Training on offset-free labels gives crisp outputs (R, Ye et al. TIP 2023).
2. Evaluation uses one-to-one pixel matching within a distance tolerance (BSDS ODS / OIS / AP), plus crispness metrics (Average Crispness AC, CEval = scoring raw maps without NMS). A credible EL benchmark should report cracks this way next to strict IoU.
3. Three families of fixes exist: refine labels before training (Canny-guided refinement), align labels during training (SEAL, STEAL, PNT-Edge, MatchED), or model annotator disagreement (UAED, RankED, MuGE, SAUGE). A fourth, newer family uses generative or iterative decoders (DiffusionEdge, GED, EasyControlEdge, MEMO).

Our two label versions (BenchmarkEL 2021 original vs 2022 revised crack / inactive masks on the same cells) are a free "second annotator" for the disagreement-modelling family.

## Minimum experiments
Baseline = house U-Net++ at 100% labels (and PF where E1 matters), 5 seeds per arm, clean-49 test plus E1, or the module-grouped 5-fold CV as the instrument. About 1.1 GPU-h per run.
1. Ridge-snapped labels (#1): arm = train on snapped + width-restored crack labels. Metrics: crack IoU, relF1@2, components >= 20 px found, E1 relF1@2, plus AC crispness. Kill if crack IoU < baseline - 0.012 and relF1@2 not up by >= 0.01. Also score against snapped test GT as a benchmark secondary. About 12 GPU-h.
2. Source-style conditioning (#3): arm = FiLM with label-width / source scalar. Key metric = per-source crack IoU (BMRK 0.379, CFVS-no-twin 0.397). Kill if no source gains >= 0.02 and overall crack IoU n.d. About 8 GPU-h.
3. RankED (#4) with UAED weighting as sub-arm (#9): arm = CE + Dice + L_Rank (+ L_Sort with 2021-vs-2022 certainty). Metrics: crack AP, relF1@2 at val-chosen threshold, strict IoU at argmax. Kill if crack AP and relF1@2 both n.d. About 15 GPU-h.
4. MatchED head (#2): arm = house + matching head (tau_d 2, tau_c 0.05). Kill if relF1@2 and component recall both n.d. and strict IoU drops. About 15 GPU-h.
5. PNT warp (#5): arm = warm-up + PSL joint training. Kill if crack IoU and relF1@2 both n.d. About 15 GPU-h.
6. Bold bet (#7): VAE reconstruction check first (crack IoU of decode(encode(GT)) vs GT; stop if < 0.8), then 1 seed on 478 cells, judged on E1 crack relF1@2 vs PF ensemble 0.43 to 0.47. Kill if below the PF single model. About 40 GPU-h.

## Overlap with BRIEF section 5 (honest)
- Offset-tolerant CE (n.d.) is the closest past run to #2 and #6 alignment: both forgive a 1 to 2 px shift. MatchED adds one-to-one matching (width control) and moves the target; STEAL / PNT-Edge learn the shift. Not closed, but the prior is weaker.
- Skeleton Recall and clDice runs touched thinness; no run changed the labels themselves. "Automatic label refinement, noise-robust training, annotator / source-style modelling" are listed as open.
- Mean Teacher / CPS were SSL runs; #13 is supervised noise-robust learning, a different condition.
- Foundation encoder probes were frozen, single-layer, linear; #7, #10 add adapters and decoders, which BRIEF lists as open.

## Notable papers rejected
- doi:10.1007/978-3-030-01219-9_24 SEAL (2018): subsumed by STEAL and PNT-Edge, which align labels the same way with better reported results.
- doi:10.1145/3830018 GED (2026): one-step Stable Diffusion edge detector, BSDS ODS 0.870; no official code (EasyControlEdge authors had to reimplement it), and the same VAE risk as #7.
- doi:10.1007/978-3-030-01231-1_35 Learning to Predict Crisp Boundaries (Dice for crisp edges) and doi:10.1109/cvpr.2017.187 Deep Crisp Boundaries: house already uses CE + Dice.
- arxiv:2507.06569 EBT loss and doi:10.1016/j.asoc.2026.114750 symmetrised WBCE: reweightings of BCE near edges; close to the offset-tolerant CE that was n.d.
- doi:10.1016/j.knosys.2025.114138 second-order-derivative crisp edges: relevant idea (cracks are valleys) but no abstract in the index and full text not read; covered by the Hessian guide in #1.
- doi:10.1109/tpami.2021.3084197 Unmixing features / tracing loss: crispness via side-output design specific to HED-style nets.
- EDTER doi:10.1109/cvpr52688.2022.00146, EDMB doi:10.1109/wacv61041.2025.00746, EDCSSM doi:10.1109/tcsi.2025.3587240, A new baseline for edge detection doi:10.1016/j.image.2026.117485: architecture-only detectors for natural images; transformer / Mamba segmenters belong to other directions.
- doi:10.1109/tits.2023.3307286 CarNet: lightweight pavement crack net, ODS 0.514 on Sun520; no mechanism for label noise.
- arxiv:2407.19992 (Shu, high-precision ED with 1 px tolerance): argues for a stricter tolerance; useful only as a benchmark discussion point.

## Benchmark notes (S)
- Report crack (and gridline) with BSDS-style one-to-one matching at 1 and 2 px: ODS, OIS, AP. Check that our relF1@2 uses one-to-one matching; a dilation-based relaxed F1 lets thick predictions match many GT pixels.
- Add a crispness number (AC from #1, or CEval as in #2, #7, #12) so thick predictions cannot score well on relaxed metrics.
- With two label versions on the same cells, an agreement-weighted score in the RankED style is cheap and principled, and it measures the label ceiling directly.
- Suite members from this field: PiDiNet and TEED (light), RankED (loss), MatchED (newest plug-in, CVPR 2026), DiffusionEdge (generative), SAUGE (SAM-based).

## Gaps
- search_snippets was rate-limited in both passes, so numbers for STEAL, MuGE, SAUGE, DiffusionEdge come from abstracts only.
- No paper applies edge-detection label alignment to EL cracks or to an industrial crack set; no evidence on our domain.
- Code not verified for Guided Label Refinement, EasyControlEdge, PEdger; MatchED code status conflicting.
- Sub-directions worth their own search: (a) dark-ridge / Hessian detectors as label guides for curvilinear structures (vessels, roads); (b) BSDS-style evaluation code ported to multi-class segmentation; (c) multi-rater modelling in medical segmentation, close to #3 and #4.
